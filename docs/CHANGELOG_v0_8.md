# SARAKURA v0.8 changelog

## Added

- `automation_plan.json` and `automation_plan.md` are generated by `gb analyze` / `fc analyze`.
- `sarakura automation-plan` command was added.
- Automation commands are generated for KOKURA/KUROSAKI debug automation flows:
  - reproduce by breaking on diagnostic event type
  - inspect by re-entering the suspect PC or diagnostic context
  - retest by re-running emulator diagnostics and SARAKURA analysis
- `repro_bundle.zip` now includes `automation_plan.json` and `automation_plan.md`.
- `schemas/sarakura_automation_plan.schema.json` was added.
- Core unit tests for automation plan generation were added.
- CLI smoke tests for automation plan generation were added.

## Purpose

v0.8 connects SARAKURA diagnostics to emulator automation.  This is the bridge from
`ai_diagnostics.json` / `repair_plan.json` to KOKURA/KUROSAKI Python bindings and CLI-driven
reproduction workflows.

This release is intentionally aligned with the project goal of exceeding Mesen2 Lua scripting in
AI-assisted repair loops: SARAKURA does not only say what is wrong; it also emits the commands needed
to reproduce, inspect, and retest the issue.
